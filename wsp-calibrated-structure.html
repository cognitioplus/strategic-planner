Understanding "Shifting the Burden" Archetype

A systems dynamics archetype showing how problem-solving through symptomatic fixes can create dependency and prevent fundamental solutions.

🔄 The Causal Loop: From Symptom to Dependency

⚠️ Reinforcing Loop (Symptomatic Fix)

Problem Appears → Apply Temporary Fix (JO/Borrowed) → Problem Subsides (Short-term) → Pressure Reduces ↻

Result: Growing dependency on temporary fixes. The underlying cause remains unaddressed, so the problem inevitably returns with greater urgency.

✓ Balancing Loop (Fundamental Solution)

Problem Appears → Build System (Plantilla) → Root Cause Resolved → Permanent Stability

Result: Sustainable resolution. Initial investment in permanent structure yields long-term stability and institutional resilience.

📊 WSP's Current State: Caught in the Symptom Loop

The Problem: Inconsistent technical expertise and institutional memory loss due to staff turnover
Current Symptomatic Fix: Hiring temporary Job Orders (JOs) and borrowing staff from other TESDA units
Short-term Result: Problems temporarily managed, but expertise leaves when contract ends
Long-term Cost: Loss of institutional knowledge, repeated hiring cycles, dependency on "borrowed" capacity

🎯 WSP's Path Forward

Temporary JOs ⟹ Permanent Plantilla + MOP

By implementing a permanent Secretariat with documented systems (MOP), WSP shifts from treating symptoms to solving the fundamental problem of institutional continuity.

💡 Key Insight #1: The "Shifting the Burden" Trap

Organizations that continually rely on temporary staff are actually experiencing a reinforcing feedback loop. Each temporary fix removes pressure to implement permanent solutions, deepening the dependency.

💡 Key Insight #2: Institutional Memory as a Strategic Asset

Institutional memory (embodied in people and documented in systems) is what allows organizations to learn from experience and improve over time. When knowledge leaves with departing staff, the organization "forgets" and must relearn lessons.

💡 Key Insight #3: System vs. Process Dependency

Process-Dependent: Success depends on individual skill and effort (fragile, person-dependent)
System-Dependent: Success depends on documented workflows and permanent roles (resilient, scalable)

Source: Systems Dynamics modeling based on Senge (1990) & Kim & Anderson (2011).
